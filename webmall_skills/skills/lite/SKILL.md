# WebMall Shopping Skill (lite)

Short rules for finishing tasks and submitting the right offers.

## 1. Always submit something

- A run stops after 50 actions or about 50 minutes. An answer that was never submitted scores 0; a partial answer still earns credit.
- Do one focused pass per shop (one or two queries, then the relevant result pages) and move on. Do not repeat a query that brought nothing new.
- By about action 30, stop searching: finish any checkout, then submit the offers in your ledger.
- Keep `<think>` to a few sentences and `<memory>` to the ledger plus your next step. Long notes slow down every later step and get cut off.

## 2. Only submit URLs you have opened

- Links in result lists do not show their URL, and product URLs do not match the titles. Guessed URLs are almost always wrong.
- Open every offer you plan to submit and copy the URL of the open tab exactly. Never build a URL from a title or from memory.
- Keep one ledger line per offer: `shop | title | price | URL copied from the tab`.

## 3. Submitting

- On the solution page, fill the text box, then click **Submit Final Result**. Filling the box alone submits nothing.
- A successful submission ends the task. If you still see the form with your text in it, the result was not submitted, so click the button. Never claim a confirmation that is not on the page.

## 4. Checkout

- An order is placed only when the URL contains `/checkout/order-received`. Stay on checkout until you see that page.
- If **Place order** leaves you on `/checkout/`, read the error notice, refill the fields it names, and click again.
- Country / Region and State / County are search boxes, not text fields: click the box, type in its search field, then pick the option.
- Go to the solution page only after the order-received page has appeared.

## 5. Picking the right offers

- Match the requested product type exactly. An accessory, adapter, cover or refurbished unit is not the product itself unless the task asks for it. A model name with an extra suffix, a different generation or a different capacity is a different product.
- For a numeric requirement, read the actual value on the product page and compare it with the threshold.
- For a vague request, first name the one concrete product type that fits every clue, then search for that type.
- For "all offers" tasks, the same product is often sold in several shops, and one shop can have several matching listings. Submit one URL per qualifying listing and none that fails a requirement.
- For cheapest-offer tasks, compare the matching offers from all four shops, then submit every offer at the minimum price (ties to the cent) and nothing else.

## 6. Searching

- Submit a search by pressing Enter in the search field.
- A click that reports a timeout often worked anyway because the page was still loading. Check the URL and page before you retry.
- If a search finds nothing, use a shorter query: brand plus model number, the product-type word, or a common abbreviation or synonym. Titles may give attributes such as colour in another language or as a code, so check listings the query might have missed.
