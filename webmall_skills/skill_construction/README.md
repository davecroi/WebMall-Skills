# skill_construction — building the WebMall base skill

Not part of upstream WebMall. These scripts produce the base skill
`webmall_skills/skills/base/SKILL.md` from allowed sources, scripted shop exploration
and one LLM draft. Every step writes a provenance file into
`webmall_skills/skills/base/construction/`.

- Method and rationale: see [Design](#design) below
- Outputs: see `../skills/README.md`
- Contamination checker (shared with SkillOpt): `webmall_skills/contamination.py`

**Contamination rule:** knowledge about the *environment* (how the shops and the
solution page behave) and the *task categories* is allowed; knowledge about *task
instances* (task texts, products, expected answers) is not.

## Design

### Contamination rule

Knowledge about the **environment** (how the four shops and the solution page
behave) and about the **task categories** (abstract descriptions) is allowed.
Knowledge about **task instances** is not. Allowed inputs:

- the general instruction block (identical in every task);
- the 11 category descriptions from `website/index.html`, with the example tasks removed;
- the agent prompt layout from `examples/task_message.txt`, with task-specific parts removed;
- behaviour observed by exploring the shops with made-up probe terms.

Not allowed in the skill or in any input used to write it:

- task texts, product names, products or prices from tasks, expected answer URLs;
- the per-task `motivation` field in `task_sets.json` (it describes instances,
  e.g. how many shops offer the product);
- the example tasks shown in the WebMall website category table;
- the contents of `examples/` except the general instruction block and the prompt
  layout (all four files contain real tasks; `task_message*.txt` also contain a real
  answer URL);
- catalogue knowledge from exploration (which shop sells which product, prices).

The blocklist is built automatically from `examples/task_strings.txt` and the
BrowserGym WebMall task definitions (`task_sets.json`). Probe terms are checked
strictly (any shared stemmed word rejects the term); documents are checked for model
tokens, 3-word task phrases and answer slugs. The base skill is **frozen before any
benchmark run** and is not tuned on benchmark results.

### Process

1. **Sources** → `sources.md` (generated by `build_sources.py`), checked for contamination.
2. **Probe terms** → `probe_terms.txt`: 8–10 made-up generic product types, all passing
   the strict check (`probe_terms_check.txt`).
3. **Shop exploration** → `evidence/` + `summary.json`: BrowserGym's
   `browsergym/openended` task driven with the agent's own actions; search, navigation,
   product page, cart and checkout (no order placed) and the solution page, in all
   four shops. No LLM calls.
4. **Findings** → `findings.md`, written by hand from the evidence: behaviour only,
   never inventory or prices. A finding becomes a rule only if it holds in ≥ 2 probes,
   otherwise it is a one-off observation.
5. **LLM draft** → `draft_SKILL.md`: exactly one call to `gpt-6.1-sol` with
   `draft_prompt.md` + `sources.md` + `findings.md` and nothing else (≤ 800 words, no
   product names/prices/inventory, every rule traceable to a source or finding).
   Committed unedited.
6. **Contamination check** of the draft with the trace stripped → `SKILL.md`
   (`doc` mode: 0 hits; `words` mode → `skill_word_overlap.txt`).
7. **Human review** → `review_checklist.md`; the git diff from the draft documents
   every human change.

### Why the skill has this structure

The structure is modelled on SkillOpt's ALFWorld seed skill:

1. **Overview + output format:** always `<think>` (and `<memory>`) and exactly one
   `<action>…</action>`; never reply in plain text.
2. **Environment:** the four shops, the solution page and submission rules, shop
   behaviour from the findings.
3. **Task category table:** 11 rows — category → goal → key steps, from the category
   descriptions.
4. **General principles.**
5. **Common mistakes to avoid.**

The format rule is part of the skill because cutting parse-error retries is a
legitimate efficiency gain; format-error retries per step are reported as a separate
metric to keep its effect attributable. `gpt-6.1-sol` is not an evaluated model, but
it is from the same family as the evaluated `gpt-6-luna`.

## Files

| File | What it does | Writes |
|---|---|---|
| `../contamination.py` (`webmall_skills.contamination`) | Loads the 91 benchmark tasks (`Browsergym/.../webmall/task_sets.json` + `examples/task_strings.txt`), builds a blocklist (task words, 3-word phrases, model tokens like `5900x`, expected-answer URL slugs) and checks text against it. Three CLI modes (see below). Shared with SkillOpt's leakage guard, so it lives outside this subpackage. | nothing (prints) |
| `build_sources.py` | Assembles the allowed sources: the general instruction block shared by all tasks, the 11 category descriptions from `website/index.html` (example tasks removed, overlapping phrases paraphrased via `REDACTIONS`), and the agent prompt layout from `examples/task_message.txt` (goal, observation and history replaced by placeholders). | `construction/sources.md` |
| `explore_shops.py` | Drives the four shops and the solution page through BrowserGym's `browsergym/openended` task with the agent's own actions (`fill`, `click`, `keyboard_press`, `goto`) and saves the flattened AX tree the agent would see. Probes search (Enter vs. button, no-results, long vs. short query), product page, cart and checkout (**never places an order**). No LLM calls. | `construction/evidence/*.txt`, `construction/evidence/summary.json` |
| `draft_skill.py` | Makes **one** OpenAI call to `gpt-6.1-sol` (`reasoning_effort="high"`, no temperature — the model only supports the default) with `draft_prompt.md` + `sources.md` + `findings.md`, and saves request, response and draft verbatim. | `construction/draft_request.json`, `draft_response.json`, `draft_SKILL.md` |
| `tests/` | Unit tests for the pure logic of the three scripts (no network, no browser). The contamination tests are in `webmall_skills/tests/test_contamination.py`. | — |

`draft_request.json` and `draft_response.json` are written on every re-run of
`draft_skill.py` but are intentionally **not committed** in this repo (they are
git-ignored in `skills/base/construction/`). The originals are kept in the thesis
repo; `construction/NOTES.md` ("Not included in this repo") records their parameters,
token usage and that the response content equals `draft_SKILL.md`.

`webmall_skills.contamination` modes:

```bash
python -m webmall_skills.contamination terms FILE     # strict: reject terms sharing any (stemmed) word with a task; exit 1 on reject
python -m webmall_skills.contamination doc FILE...    # model tokens, 3-word task phrases, answer slugs; exit 1 on hit
python -m webmall_skills.contamination words FILE     # list every word whose stem is task vocabulary, for manual sign-off; always exit 0
```

`doc` does not catch one- or two-word product names; that is what `words` is for
(see `construction/NOTES.md`).

## Prerequisites

- Run everything from the repo root with the BrowserGym venv: `PY=Browsergym/.venv/bin/python`
- `pytest` in that venv (`$PY -m pip install pytest`)
- The Docker shops running (`http://localhost:8081`–`8085`, see `.env` and `docker_all/README.md`)
- `OPENAI_API_KEY` in `.env` at the repo root (only for the draft step)

## Running the process

The base skill is **frozen** — re-running these steps overwrites its provenance
files. Run them only to reproduce the method (e.g. on a fresh checkout) or after
deliberately copying this subpackage for a new skill variant (see
[Reworking the base skill](#reworking-the-base-skill)).

```bash
# from the repo root
PY=Browsergym/.venv/bin/python
C=webmall_skills/skills/base/construction

# 0. Tests
$PY -m pytest webmall_skills/skill_construction/tests webmall_skills/tests/test_contamination.py -q

# 1. Allowed sources → construction/sources.md, then check it
$PY -m webmall_skills.skill_construction.build_sources
$PY -m webmall_skills.contamination doc $C/sources.md
#    Expected: only hits from the shared general instruction block (documented in sources.md)

# 2. Probe terms: edit construction/probe_terms.txt, then
$PY -m webmall_skills.contamination terms $C/probe_terms.txt \
  | tee $C/probe_terms_check.txt                            # must exit 0, ≥ 8 terms

# 3. Shop exploration (several minutes, headless browser)
$PY -m webmall_skills.skill_construction.explore_shops

# 4. Findings: write construction/findings.md by hand from evidence/ and summary.json
#    (behaviour only, no products/prices; "rule" needs ≥ 2 probes), then
$PY -m webmall_skills.contamination doc $C/findings.md

# 5. Draft — exactly one call; do not re-run for a "better" draft
$PY -m webmall_skills.skill_construction.draft_skill

# 6. Final skill: strip the trace, check, review
$PY -c "from pathlib import Path; d=Path('$C/draft_SKILL.md').read_text(); Path('webmall_skills/skills/base/SKILL.md').write_text(d.split('---TRACE---')[0].rstrip()+'\n')"
$PY -m webmall_skills.contamination doc webmall_skills/skills/base/SKILL.md
$PY -m webmall_skills.contamination words webmall_skills/skills/base/SKILL.md > $C/skill_word_overlap.txt
wc -w webmall_skills/skills/base/SKILL.md                   # ≤ 800
#    Then the human review: edit SKILL.md, fill construction/review_checklist.md, commit.
```

Commit the raw draft before any human edit, so the git diff documents every change.

## Reworking the base skill

This subpackage (`webmall_skills/skill_construction/`) and its records
(`webmall_skills/skills/base/construction/`) form one unit and can be replaced or
deleted together without touching the rest of `webmall_skills`. The only shared
dependency is `webmall_skills.contamination` (also used by SkillOpt's leakage
guard), which therefore lives in the package core and must stay.

To build a different skill variant instead of overwriting the frozen base skill:

1. Copy this folder (e.g. to `webmall_skills/skill_construction_v2/`).
2. Change `CONSTRUCTION_DIR` / `OUT_PATH` in the copies to
   `SKILLS_DIR / "<name>/construction"`, and the model in `draft_skill.py` if needed.
3. Run the process above with the new module names; the final skill goes to
   `webmall_skills/skills/<name>/SKILL.md` and is selectable as `skill = "<name>"`.

## Known limitations

- `_stem` is a crude plural stripper (`es`/`s`/trailing `e`); it errs on the strict side.
- Button clicks in `explore_shops.py` use BrowserGym's 500 ms timeout and retry once;
  remaining timeouts are recorded as `action_error` in `summary.json` and must be
  excluded from findings.
- The long/short-query probe takes the first `<h1>` on a product page; on Hardware Cafe
  that is the site title, so that probe is invalid there.
- Output paths are fixed to `skills/base/construction` and the model is fixed to
  `gpt-6.1-sol`. To build a different skill variant, copy this folder (see
  'Reworking the base skill').
- `construction/sources.md` still says it was generated by
  `skill_construction/build_sources.py` (the thesis path); the generator keeps that
  line unchanged so a re-run reproduces the committed file byte for byte.
