# skills — skill files for the WebMall agent

Not part of upstream WebMall. Each subfolder holds one skill condition
that `run_webmall_study.py` / `run_single_task.py` can inject into the agent's prompt:

```python
skill = "base"   # None = no-skill baseline; or "skillopt", or a path to a .md file
```

The skill is inserted into the user message at every step under `## Skill Knowledge`
(same wrapper as SkillOpt's ALFWorld environment); see `../docs/skill_injection.md`.

## `base/` — the base skill

The hand-curated starting skill: one evaluated condition and the seed for the
self-improvement phase. It is **frozen** once benchmark runs start; later changes
belong to the self-improved skill variants. It was built with the scripts in
`webmall_skills/skill_construction/` (how to run them: `webmall_skills/skill_construction/README.md`).

| File | What it is |
|---|---|
| `SKILL.md` | **The base skill** (≤ 800 words): output format, environment and shop behaviour, task-category table, general principles, common mistakes. |
| `construction/sources.md` | Allowed sources given to the drafting model: general instruction block, category descriptions without example tasks, agent prompt layout. Generated by `build_sources.py`. |
| `construction/probe_terms.txt` | Made-up search terms used to explore the shops. |
| `construction/probe_terms_check.txt` | Strict contamination check of the probe terms at exploration time (all pass). |
| `construction/evidence/` | Raw exploration output: one AX-tree file per shop and scenario (`<shop>__<scenario>[__<term>].txt`) plus `summary.json`. **Audit only** — contains catalogue content and was never given to the drafting model. |
| `construction/findings.md` | Behaviour-only findings from the evidence (ID, status rule/one-off, shops, probes, evidence files, why it matters). The only exploration input to the draft. |
| `construction/draft_prompt.md` | The fixed drafting prompt. |
| `construction/draft_SKILL.md` | Raw draft, unedited, including a `---TRACE---` section mapping each instruction to a source section or finding ID. |
| `construction/skill_word_overlap.txt` | Words of `SKILL.md` that also occur in task texts, for manual sign-off. |
| `construction/review_checklist.md` | Human review checklist with automated results (contamination, word/token count, render check). |
| `construction/NOTES.md` | Method notes for the thesis appendix: scope of the contamination check, model parameter probe, disclosures, environment versions. |

**Provenance chain:** `sources.md` + `findings.md` (← `evidence/` ← `probe_terms.txt`)
→ `draft_prompt.md` → (`gpt-6.1-sol`) → `draft_SKILL.md` → (trace stripped, human review) → `SKILL.md`.
The single human edit after the LLM draft is documented in `base/construction/NOTES.md` /
`review_checklist.md` (thesis repo commit `8f40746`).

## `skillopt/` — the SkillOpt-evolved skill (C3)

Generated by `python -m webmall_skills.skillopt_webmall.export_lineage <run_dir>` from a SkillOpt run
on the train/val split (`webmall_skills/skillopt_webmall/`). `SKILL.md` is the best skill;
`HISTORY.md` and `history/` record every candidate edit, including rejected ones, and
which versions became the new best. See `skillopt/README.md`.

## Adding a skill

1. Create `webmall_skills/skills/<name>/SKILL.md` (e.g. `webmall_skills/skills/self_improved/SKILL.md`) and keep its provenance next to it.
2. It is immediately selectable as `skill = "<name>"` in `run_webmall_study.py` /
   `run_single_task.py`; no code change is needed.
3. Do not edit `base/SKILL.md`.
